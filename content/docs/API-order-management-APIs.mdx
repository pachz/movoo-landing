# Endpoints (Shop → Muvx)

## 1. Create Order

`POST /v1/orders`

Creates a new delivery order in Muvx.

### Request Body

```json
{
  "integration_order_id": "SHOP123456",
  "pickup": {
    "name": "Store Name",
    "address": "789 Elm St, Kuwait City",
    "lat": 29.3375,
    "lng": 48.0286,
    "phone": "+96500000000"
  },
  "dropoff": {
    "name": "Customer Name",
    "address": {
      "area": "Salmiya",
      "block": "3",
      "street": "Al Muqawil",
      "building": "21A",
      "floor": "1",
      "flat": "2"
    },
    "lat": 29.3759,
    "lng": 47.9774,
    "phone": "+96511111111"
  },
  "items": [
    {
      "name": "Product A",
      "quantity": 2,
      "price": 1.25,
      "weight": 0.53
    }
  ],
  "notes": "Leave at the door",
  "cod_amount": 3.5,
  "destination_id": "ks7fzcatg65zdv4b1plihw0qz57q5qcs",
  "auto_pickup": true,
  "scheduled_pickup_time": "2025-07-16T15:00:00Z"
}
```

<Banner title="Address Fields">
  Address fields can be provided either as a plain string or as a structured object. <code>lat</code> and <code>lng</code> are optional but improve delivery accuracy.
</Banner>
<div className="mt-6"></div>
<Banner title="Destination Routing">
  • If you provide <code>destination_id</code>, the order will be created for that specific destination.  
  • If omitted, the order will automatically route to the Source’s <strong>default</strong> destination.  
  • You can fetch available destinations (and see which one is default) via the <a href="/documentation/api-order-management#4-destinations-list">Destinations List</a> API or in the panel under <em>Source &rarr; Overview</em>.
</Banner>

<div className="mt-6"></div>
<div className="inline-block bg-green-100 text-green-800 text-sm font-semibold px-3 py-0 rounded">
  200 OK Response
</div>

```json
{
  "success": true,
  "id": "MOV123",
  "status": "created",
  "tracking_url": "https://sample.com/track/MOV123", // optional
  "status_url": "https://api.sample.com/v1/orders/MOV123/status"
}
```

<div className="inline-block bg-red-100 text-red-800 text-sm font-semibold px-3 py-0 rounded">
  400 Bad Request
</div>
```json
{
  "success": false,
  "error": "validation_error",
  "message": "Missing required field: dropoff.phone"
}
```

<div className="inline-block bg-yellow-100 text-yellow-800 text-sm font-semibold px-3 py-0 rounded">
  409 Conflict
</div>
```json
{
  "success": false,
  "error": "duplicate_order",
  "message": "An order with this integration_order_id already exists."
}
```

## 2. Cancel Order

`POST /v1/orders/{id}/cancel`

Cancels a previously created order.

<div className="inline-block bg-green-100 text-green-800 text-sm font-semibold px-3 py-0 rounded">
  200 OK Response
</div>
```json
{
  "success": true,
  "id": "MOV123",
  "status": "cancelled"
}
```

<div className="inline-block bg-gray-100 text-gray-800 text-sm font-semibold px-3 py-0 rounded">
  404 Not Found
</div>
```json
{
  "success": false,
  "error": "not_found",
  "message": "Order not found"
}
```

<div className="inline-block bg-red-100 text-red-800 text-sm font-semibold px-3 py-0 rounded">
  400 Bad Request
</div>
```json
{
  "success": false,
  "error": "invalid_action",
  "message": "Cannot cancel an order that has already been delivered."
}
```

`GET /v1/orders/{id}/status`

Fetches the latest delivery status of a given order.

<div className="inline-block bg-green-100 text-green-800 text-sm font-semibold px-3 py-0 rounded">
  200 OK Response
</div>
```json
{
  "success": true,
  "id": "MOV123",
  "integration_order_id": "SHOP123456",
  "status": "in_transit",
  "last_updated": "2025-07-16T09:42:00Z"
}
```

<div className="inline-block bg-gray-100 text-gray-800 text-sm font-semibold px-3 py-0 rounded">
  404 Not Found
</div>
```json
{
  "success": false,
  "error": "not_found",
  "message": "Order not found"
}
```

## 4. Trigger Pickup

`POST /v1/orders/{id}/pickup`

Manually triggers a pickup for an existing order if auto-pickup is disabled or delayed.

<div className="inline-block bg-green-100 text-green-800 text-sm font-semibold px-3 py-0 rounded">
  200 OK Response
</div>
```json
{
  "success": true,
  "id": "MOV123",
  "status": "dispatched"
}
```

<div className="inline-block bg-gray-100 text-gray-800 text-sm font-semibold px-3 py-0 rounded">
  404 Not Found
</div>
```json
{
  "success": false,
  "error": "not_found",
  "message": "Order not found"
}
```

<div className="inline-block bg-red-100 text-red-800 text-sm font-semibold px-3 py-0 rounded">
  400 Bad Request
</div>
```json

  "success": false,
  "error": "invalid_status",
  "message": "Pickup cannot be triggered. Current status: picked_up"

```

## 4. Destinations List

`GET /v1/destinations`

Returns all Active destinations linked to the calling Source (the Source is inferred from the API key used to call this endpoint).
Use the returned id to target a specific destination when creating an order — pass it as destination_id in Create Order (POST /v1/orders) to route the order to that destination.


<div className="inline-block bg-green-100 text-green-800 text-sm font-semibold px-3 py-0 rounded">
  200 OK Response
</div>

```json
{
  "success": true,
  "destinations": [
    {
      "id": "ks7871ycvns4h4nx530c0ss0ks7q4dqt",
      "name": "beep beep DMS",
      "is_default": true,
      "environment": "sandbox",
      "provider": "beepbeep"
    },
    {
      "id": "ks7fzcatg65zdv4b1gmqhw0qz57q5qcs",
      "name": "autobot test",
      "is_default": false,
      "environment": "sandbox",
      "provider": "autobot"
    }
  ]
}
```

<Banner title="Notes">  
  • Only destinations with status **Active** are returned.  
  • Each destination includes its `environment` (`sandbox` or `production`) and `provider` identifier.  
  • Exactly one destination per Source is always marked as `is_default: true`.  
</Banner>
